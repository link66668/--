# 部署与接口

## 比赛交付目标与实施范围

以下为 2026-10-04 确认的项目预期与开发范围。

项目用于参加**软件设计赛**，预期部署到 **2 核 CPU、4 GB 内存服务器**。用户通过服务器地址访问项目，后续交付入口如下：

| 入口 | 预期使用方式 | 当前状态 |
| --- | --- | --- |
| 网页 | 电脑或手机浏览器访问服务器地址 | 现有开发与验证入口 |
| Windows EXE | 安装或启动桌面软件，连接同一服务器 | 后续目标，暂不打包或改造客户端 |
| Android APK | 安装手机软件，连接同一服务器 | 后续目标，暂不打包或改造客户端 |

各入口复用同一后端服务与账号体系，同一账号同步资料、训练计划、饮食记录、会话和评估报告。具体服务器地址、客户端封装技术及地址配置方式，待开始部署和打包时确定。

开发时保持以下分工：

- **项目服务器**：执行营养、食谱、RM、训练排期和成就等业务计算，保存账号与数据，处理同步及 AI 请求转发，向客户端返回结果。
- **用户设备**：执行视频解码、MediaPipe Lite（快速）／Full（标准，默认）／Heavy（高精度） 姿态推理、人物跟踪、角度测量和关键帧提取，并负责界面、视频播放与 3D 渲染。后续 EXE、APK 也按使用用户设备算力的目标实现和验证。
- **用户配置的 AI 供应商**：执行对话、餐食识别、规划建议和动作点评。

**当前只记录上述预期，继续完善网页项目；不启动 EXE、APK 打包或客户端改造。** 后续实现客户端时，需要在实际运行环境中验证视频分析、文件选择、数据同步和渲染能力。2 核 4 GB 是服务器配置约束，承载量需在目标服务器上实测。

## 启动

需要 **Node.js 24 或更高版本**。主应用使用 Node 内置 HTTP、SQLite 和加密模块，没有 npm 运行依赖。

生产环境建议使用 Node.js 24 LTS，参见 [Node.js 发布状态](https://nodejs.org/en/about/previous-releases)。当前部署不需要 Python、CUDA 或服务器 GPU。

## 2 核 4 GB 的部署方案

服务器执行营养、食谱、RM、训练排期和成就等业务计算，并保存账号与记录、转发 AI 请求。视频解码、MediaPipe Lite／Full／Heavy 姿态推理、角度测量和关键图片提取在每位用户自己的浏览器执行，用户无需安装程序。标准档 MediaPipe Full 默认启用，三档都使用原生米制三维坐标计算角度并向 AI 提供 17 个身体点。3D 演示也由用户设备渲染。

| 项目 | 小规模上线建议 |
| --- | --- |
| CPU / 内存 | 2 vCPU / 4 GB；先用单个 Node 服务实例 |
| 磁盘 | 40–60 GB SSD 起步；餐食图片、附件、数据库和备份会持续占用空间 |
| 公网带宽 | 5–10 Mbps 起步；模型和 3D 资源的首次下载速度受带宽影响 |
| 操作系统 | 64 位 Linux 或 Windows，安装 Node.js 24 LTS |
| 访问方式 | IP 可用于测试；正式使用配置域名、可信 HTTPS 证书及反向代理 |
| AI | 每位用户配置自己的供应商和 API Key；服务器不托管生成式大模型 |

以上是针对当前分工的起始配置建议，不是压测容量承诺。1–2 人同时分析视频时，主要推理负载落在各自设备上；服务器仍需承担网页及模型分发、AI 数据转发和同步。不要把更高档服务器上的视频推理测速换算成这台 2 核服务器的承载量。

MediaPipe 运行库与所选档位权重首次按需下载，模型和哈希见 [MediaPipe 三档接入](MediaPipe三档接入.md)。三档分别加载，切换至未缓存档位需要额外下载。模型文件使用流式静态响应，由用户设备执行推理；高精度 Heavy 的分析时间更长。动作评估必须配置支持图片输入的 AI，手机与低性能设备需要实际验证可用内存和分析速度。

营养、RM、食谱、排期等结果必须连接服务器获取。浏览器缓存原始记录和已返回的数据；断网时不再运行这些业务公式。恢复连接后继续同步与计算。

## 启动命令

```powershell
node --version
npm start
```

电脑访问 `http://localhost:3000`。首次打开后注册账号，再完成个人建档。AI 功能在「个人设置 → AI 服务」中配置：选择预设供应商、填写 API Key、获取并勾选模型，再为各任务选择模型。提供 12 家预设及自定义供应商；未配置时会明确提示。数据默认写入项目 `.data` 目录。

```powershell
# 以下仅为自定义配置示例；按需设置。
$env:PORT = '3000'
$env:HOST = '127.0.0.1'
$env:DATA_DIR = 'D:\FitnessData'
$env:COOKIE_SECURE = 'true'
$env:ALLOW_PRIVATE_AI = 'false'
npm start
```

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址；反向代理部署可设为 `127.0.0.1` |
| `DATA_DIR` | 项目 `.data` | SQLite 数据库、服务器加密密钥和 `community-media/` 社区媒体目录；相对路径按启动目录解析 |
| `COOKIE_SECURE` | `false` | `true` 时 Cookie 仅通过 HTTPS 发送；本机纯 HTTP 调试不要开启 |
| `ALLOW_PRIVATE_AI` | `true` | 允许本机与局域网模型；开放给非可信用户时应设为 `false` |
| `COMMUNITY_MODERATOR_IDS` | 空 | 拥有社区管理权限的账号 ID，多个值用英文逗号分隔 |
| `COMMUNITY_MODERATOR_EMAILS` | 空 | 拥有社区管理权限的账号邮箱，多个值用英文逗号分隔；按小写匹配 |

主应用提供 `public` 内的网页资源；`/model/` 仅提供精细模型所需文件和署名许可白名单。不会把项目源码、数据库、Excel、开发依赖或任意磁盘文件作为静态目录公开。

社区管理员只能由服务端配置授权。选择实际管理账号后设置上述变量并重启服务，例如 `$env:COMMUNITY_MODERATOR_EMAILS = 'admin@example.com,reviewer@example.com'`；未配置时所有普通账号均不能访问管理队列。也可在项目根目录的本地 `.env` 中保存配置；`node server.mjs`、`npm start` 和 `npm run dev` 启动时会自动读取，已有环境变量优先。建议使用已注册账号的 `COMMUNITY_MODERATOR_IDS` 绑定授权；本地 `.env` 已被 Git 忽略，不应提交真实配置。配置是权限来源，移除配置并重启会撤销授权，客户端不能通过修改社区资料或请求字段授予自己角色。管理员可查看举报原文、填写原因后保留、下架或恢复内容。

## 手机、HTTPS 和离线使用

同一局域网内，手机可访问 `http://电脑局域网IP:3000`，前提是电脑防火墙允许该端口，且服务仍在运行。账号和数据属于这一个服务实例；电脑和手机必须连接同一个实例。

完整 PWA、Service Worker、设备相机接口和 WebGPU 需要浏览器认可的安全上下文。手机使用普通局域网 HTTP 地址时，浏览器可能禁用这些能力。MediaPipe 无法启用 GPU 时回退同一档位的浏览器 WASM CPU，速度可能明显降低。建议通过具有可信证书的 HTTPS 域名反向代理到本服务。`localhost` 的开发例外不适用于手机上的电脑局域网 IP。

反向代理需要：

- 保留浏览器请求的 `Host`，保证 `Origin` 与 `Host` 一致；服务端会拒绝跨站写请求。
- 私有附件的 Base64 JSON 请求需要至少 `12 MB` 的请求体；MediaPipe 完整骨架和测量请求上限为 `40 MiB`，社区单个二进制视频上传最大 `50 MiB`，代理请求体限制统一建议设为 `60 MiB`。普通 JSON 接口仍使用各自限制，动作评估原视频不会上传。
- 上传和请求体读取超时建议至少 `90` 秒；Node 服务的请求读取超时为 `90` 秒。AI 上游读取超时建议 `300` 秒，并关闭 SSE 响应缓冲。保留媒体请求的 `Range` 和响应的 `Accept-Ranges`、`Content-Range`，允许 `206` 分段响应及 `416` 越界响应，保证社区视频进度拖动正常。
- 使用 HTTPS，并设置 `COOKIE_SECURE=true`。应用不会根据不可信的 `X-Forwarded-Proto` 自动启用安全 Cookie。
- 将 Node 服务限制在代理可访问的地址和端口。代理层按实际部署配置访问控制、请求频率及日志保留。

离线编辑由浏览器 IndexedDB 保存，联网后按记录版本同步。第一次使用、登录、AI 请求、上传新附件和跨设备取回数据需要联网。Service Worker 不缓存鉴权 API 和个人图片；已在服务端上传的附件无法保证离线可查看。浏览器清理站点数据也会清除尚未同步的本地记录。

社区草稿独立保存在浏览器 IndexedDB，以账号 ID 与草稿 ID 作为联合键，并保留选择的图片、视频 Blob。离线可编辑和保存本机草稿，社区发布及互动需要联网；草稿不会通过个人记录同步接口自动发布，也不会跨设备同步。Service Worker 仅缓存社区脚本和样式，不缓存社区 API 或媒体。尚未绑定有效笔记、头像、消息或评论的服务端素材七天后到期，重新打开草稿时会检查有效期，过期素材需重新上传。

社区与个人中心主页的草稿导航、编辑和缓存页面重载不依赖业务计算接口，即使计算结果缓存过期也可离线继续。训练、营养、成就等页面仍要求服务器完成业务计算；首次健康档案也需要联网校验和保存。

Nginx 反向代理的关键配置：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $http_host;
    proxy_http_version 1.1;
    client_max_body_size 60m;
    client_body_timeout 90s;
    proxy_read_timeout 300s;
    proxy_buffering off;
}
```

将这段放在已配置 HTTPS 证书的 `server` 中；应用使用 `HOST=127.0.0.1`、`COOKIE_SECURE=true`、`ALLOW_PRIVATE_AI=false`。仅通过 HTTP/IP 测试时，保持 `COOKIE_SECURE=false`，否则浏览器不会发送登录 Cookie。Nginx 参数见 [请求体限制](https://nginx.org/en/docs/http/ngx_http_core_module.html#client_max_body_size) 和 [代理超时、缓冲](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_read_timeout)。

### 业务计算接口

`POST /api/compute` 要求登录、同源请求，并检查 `X-Fitness-User` 与当前账号。请求为 `{ "operation": "estimate1RM", "args": [40, 8] }`，响应为 `{ "result": ... }`。服务只执行固定白名单中的纯函数，不接受代码、模块名或任意路径。

页面通过 `snapshot` 批量获取所选日期的营养目标、餐食合计、繁忙日、日程和成就数据；输入包含当前账号尚未同步的业务记录，因此刚编辑的内容也参与服务端计算。该接口不写入数据库，实际保存仍经原同步接口核验。客户端丢弃过期日期和账号的结果，表单输入也防止迟到响应覆盖新结果。

浏览器的静态食物、动作和公式说明来自 `public/compute-catalog.js`。修改目录定义后运行 `npm run compute:catalog`，再发布更新后的静态文件。

## AI 协议与支持边界

已实现 **OpenAI 兼容 Chat Completions、Anthropic Messages、Gemini GenerateContent** 三种协议。12 家预设包含 DeepSeek、硅基流动、Kimi、百炼国际、OpenAI、Anthropic、Gemini、OpenRouter、Groq、xAI、Mistral、Cerebras；预设地址与官方依据见 [AI 供应商](AI供应商.md)。

| 协议值 | 对话端点 | 鉴权与消息转换 |
| --- | --- | --- |
| `openai` | `POST {baseUrl}/chat/completions` | `Authorization: Bearer`；`messages`，聊天支持 `stream:true` |
| `anthropic` | `POST {baseUrl}/messages` | `x-api-key`、`anthropic-version: 2023-06-01`；独立 `system`，原生内容块；普通请求 `max_tokens:4096`，流式请求 `8192` |
| `gemini` | `POST {baseUrl}/models/{model}:generateContent`，流式使用 `:streamGenerateContent?alt=sse` | `x-goog-api-key`；`systemInstruction`、`contents`，助手角色转为 `model` |

OpenAI 兼容请求示例：

```text
POST {baseUrl}/chat/completions
Authorization: Bearer {apiKey}
Content-Type: application/json

{"model":"模型 ID","messages":[...],"stream":false}
```

常用供应商只需填写 API Key 即可获取模型。自定义地址一般包含供应商要求的版本前缀，例如 `/v1` 或 `/v1beta`；也接受以 `/chat/completions` 或 `/messages` 结尾的地址。服务端按协议构造端点。测试连接会用默认模型或指定的已启用模型发送一条简短消息，可能产生供应商调用费用。

- 模型列表由服务端实时查询，支持搜索、勾选多个模型及手动添加 ID。供应商只保存已启用的模型；`model` 是默认测试模型，任务实际使用 `tasks` 与 `taskModels` 指定的供应商和模型。
- 模型发现跟随受支持的分页游标，最多查询 10 页、返回 2000 个模型；达到上限时返回 `truncated:true`。Anthropic、Gemini、百炼使用各自分页参数。专用模型端点只用于未修改地址和协议的对应预设；自定义配置查询自身的 `/models`。
- 模型图片能力自动根据接口字段显示为支持、不支持或待确认，不按模型名称猜测；用户可在管理模型中按实际能力手动确认。尚未配置的动作点评只自动选择已启用且已确认支持图片的模型。Gemini 仅保留支持 `generateContent` 的模型，Mistral 排除明确不支持聊天的模型，百炼排除明确不输出文本的模型；其他未提供用途信息的列表可能包含非对话模型。
- 图片在 OpenAI 兼容协议中使用 `image_url`，Anthropic 使用 Base64 `image` 内容块，Gemini 使用 `inlineData`。PDF 分别使用 `file` / `file_data`、`document`、`inlineData`；实际能否识别取决于供应商和模型。
- OpenAI 兼容接口可返回 `reasoning_content`。应用以可选 `reasoningContent` 随助手消息保存，连续对话时回传，供要求保留推理上下文的模型使用。此字段不等同于 Anthropic thinking blocks 或 Gemini thought signatures；后两种结构在同轮工具调用的原生消息中保留。
- 聊天支持三种协议的流式输出，以及训练计划、日程任务和今日饮食的读取、新增、修改、删除工具调用。应用默认提供 Exa MCP 免密钥联网搜索，可按需搜索和读取公开网页；也可关闭或改用 Tavily、Brave Search。工具调用需要模型及供应商接口支持，搜索服务具有独立配置，不使用模型 API Key 作为搜索密钥。应用不提供生成式模型自动下载。完整约定见 [AI 对话](AI对话.md)和[联网搜索](联网搜索.md)。
- TXT、Markdown、CSV、JSON 按 UTF-8 文本加入上下文；单个文本附件发送给模型时不超过 `200 KB`。不解析 Word、Excel、压缩包或任意二进制文件。
- 上游请求默认超时 `60` 秒；单个用户最多同时 `3` 个 AI 请求；上游响应最多 `2 MB`。不跟随接口重定向。
- 供应商地址仅接受 HTTP/HTTPS，拒绝 URL 内的凭据、查询参数、片段及云元数据地址。发起连接前检查 DNS，并固定检查后的地址，避免二次解析切换到其他地址。禁用内网模式时也会拒绝解析到私有地址的域名。
- 服务端为对话、餐食、规划添加任务提示和用户上下文；不会声称项目已有经过专业审核的医学知识库。用户在聊天中明确要求时，AI 可执行计划、日程和今日饮食变更；只是询问建议时不记账，餐食编辑器的估算仍需确认后入账。工具操作校验账号、参数和版本，并返回实际结果。

餐食模型约定返回：

```json
{
  "items": [{ "name": "熟米饭", "grams": 150, "kcal": 116, "protein": 2.6, "carbs": 25.6, "fat": 0.3 }],
  "note": "份量来自目测，请确认。",
  "confidence": "low"
}
```

`grams` 是实际吃下的份量。`kcal` 和三大营养素均为**每 100 克**的数值；由服务器按实际份量换算。模型返回内容经服务器计算接口验证，浏览器展示草稿，用户确认后保存。

## 数据、备份和恢复

`.data` 中包含：

| 文件 | 内容 |
| --- | --- |
| `fitness.sqlite` | 用户、密码摘要、会话、记录、私有附件、加密后的供应商密钥，以及独立社区资料、笔记、互动、通知、举报和媒体元数据 |
| `fitness.sqlite-wal`、`fitness.sqlite-shm` | SQLite WAL 运行文件，运行时可能存在 |
| `server.key` | 32 字节 AES-256-GCM 服务器主密钥 |
| `community-media/` | 社区图片、视频和头像二进制文件，上传临时文件及最终 `.bin` 文件；通过鉴权接口读取，不作为静态目录公开 |

密码使用带随机盐的 scrypt 摘要；会话 Cookie 仅保存随机令牌，数据库保存令牌摘要。供应商 API 密钥使用 AES-256-GCM 加密；个人导出和浏览器读取接口不会返回明文密钥。个人记录与附件在 SQLite 中没有整库加密，应保护数据目录权限、磁盘和备份。

个人中心的「账号与安全」位于 `#settings?section=account`，点击侧边栏头像或账号名称也可进入。头像与社区资料共用同一媒体引用，支持最大 10 MiB 的 JPEG、PNG、静态 WebP；选择后先上传并预览，点击「保存头像」才正式绑定，成功后同步更新侧边栏、健康档案和社区主页，重新登录和刷新后仍保留。密码修改要求输入当前密码，并两次确认新密码；新密码为 8–256 个字符且不能与当前密码相同。修改成功保留发起请求的会话并撤销该账号其它会话，密码不会写入本机记录或同步队列。头像上传和密码修改需要联网。

**备份必须同时保留数据库、`server.key` 与 `community-media/`。** 数据库保存社区媒体引用，二进制文件保存在目录中，缺少任何一方都会丢失相应内容。该密钥绑定这个服务的数据目录，移动到另一台机器时也必须一并迁移。它不是硬件密钥；丢失后已有供应商密钥无法解密，需要重新填写。

最简单可靠的备份方法：停止服务，完整复制 `DATA_DIR` 到受保护位置，再启动服务。不要在运行时仅复制 `fitness.sqlite` 而忽略 WAL 或社区媒体。需要在线备份时使用 SQLite 支持的一致性备份工具或 API，暂停社区写入与媒体清理或采用一致的目录快照，同时保存相匹配的媒体目录及当前 `server.key`。恢复时停止服务，将完整备份放回配置的数据目录后重新启动。

用户「导出我的数据」得到可阅读的 JSON，包含记录、供应商公开配置、已启用模型、任务供应商与模型选择，以及私有附件 Base64 内容；`community` 字段包含本人的社区资料、笔记、评论、互动关系、通知、举报和媒体元数据。社区媒体导出提供鉴权地址及元数据，不内嵌图片、视频二进制内容。导出不包含密码摘要、登录会话、API 密钥和服务器主密钥，不能替代完整服务器备份。当前没有个人 JSON 一键导入界面。

升级已有数据库时，启动程序自动增加供应商预设、协议、模型列表、任务模型及配置版本字段。旧供应商按自定义 OpenAI 兼容配置保留，旧单个模型加入已启用列表；旧任务仍引用原供应商，并回退使用其原模型。已有配置从版本 1 开始，尚未配置的账号为版本 0；已有加密密钥保持不变。

社区启动时自动建立独立的 `community_*` 数据表；健康档案、训练和饮食记录继续使用原私有记录，不会自动复制到社区。首次进入社区时以账号名称建立默认社区昵称，公开作者信息只提供社区昵称、头像、简介及社区关系，不提供邮箱或健康档案。

删除账号要求再次提供密码，并级联删除该用户全部记录、附件、供应商配置及所有会话；社区同时撤下该用户笔记、清空其评论原文、清理关系与媒体文件，当前浏览器清理该账号的本机草稿，随后清理当前 WAL。删除不会修改历史备份，也不能远程擦除离线设备已经保存的数据。其他设备再次联网时无法继续使用原会话。

浏览器删除操作固定绑定发起请求的账号及其本地存储。请求响应或缓存清理期间切换账号后，旧操作只清理原账号；新账号的登录、未同步记录、附件及社区草稿保持完整。密码验证失败不清除本机记录。

## HTTP 接口

请求和响应通常使用 JSON，社区二进制上传、媒体下载和流式聊天除外。普通错误返回 `{"error":"可显示的原因"}`；流式开始后的错误通过 SSE `error` 事件返回。账号通过同源、`HttpOnly`、`SameSite=Strict` Cookie 认证。未登录返回 `401`；跨账号私有附件统一视为不存在，返回 `404`。

前端登录后应为 API 请求设置 `X-Fitness-User: 当前用户ID`。服务端对需要登录的接口及退出登录校验此请求头：若与 Cookie 对应账号不一致，返回 `409`，避免另一标签页切换账号后发送旧账号的资料、AI 上下文或设置。`/api/auth/me`、登录和注册不校验此请求头，以便重新确认当前身份。此请求头是附加身份一致性检查，不能替代 Cookie 鉴权。

### 社区接口

以下地址均以 `/api/community` 开头，沿用会话、`X-Fitness-User` 账号一致性检查和写请求的同源校验。第一期社区只向同一服务中的已登录用户展示。私人草稿留在浏览器，收藏默认私密且由本人决定是否向社区用户公开；社区媒体不使用 `/api/attachments`，不能引用私有附件 ID。

| 方法和地址 | 请求 / 响应要点 |
| --- | --- |
| `GET /feed` | `channel=recommended\|following`、`category=all\|training\|diet\|checkin\|experience\|question`，返回笔记分页 |
| `GET /search` | `q` 必填、最多 100 字，`type=notes\|users` 默认笔记；笔记可加 `category`、`sort=relevance\|latest`，用户通过昵称或完整公开账号查找 |
| `GET /topics` | 可选 `q` 最多 20 字，返回最多 20 个已发布内容使用的话题建议 |
| `POST /notes` | `{clientMutationId,title,body,category,topics,type,media}`，返回 `{note}`；媒体必须先上传 |
| `GET /notes/{id}` | 返回普通可见的 `{note}`；下架、删除内容统一 `404` |
| `PATCH /notes/{id}` | 当前作者提交完整笔记字段及 `version`，可选 `clientMutationId`；返回更新后的 `{note}`，版本不符 `409` |
| `DELETE /notes/{id}` | 当前作者提交 `{version,clientMutationId?}`，返回 `{ok:true}` 并回收本篇媒体 |
| `PUT /notes/{id}/like`、`PUT /notes/{id}/collection` | `{active:true\|false}`；返回服务端确认的关系状态和计数，重复请求不重复计数 |
| `GET /notes/{id}/comments` | `sort=latest\|hot`；返回顶层评论分页、前两条回复预览及 `commentCount` |
| `POST /notes/{id}/comments` | `{clientMutationId,body?,imageIds?,parentId?,replyToCommentId?}`；回复归入顶层评论，返回 `{comment,commentCount}` |
| `GET /comments/{id}/replies` | 读取该顶层评论的回复分页 |
| `GET /comments/{id}/context` | 返回 `noteId`、`topLevelComment`、`targetComment` 和目标附近最多 20 条回复，用于通知定位 |
| `PUT /comments/{id}/like` | `{active:true\|false}`，返回 `liked` 与 `likeCount` |
| `DELETE /comments/{id}` | `{clientMutationId?}`；评论作者或笔记作者可删除，返回 `{ok:true,commentCount}`；有回复的顶层评论保留删除占位 |
| `GET /users/{id}`、`GET /users/{id}/notes` | 作者的公开社区资料及已发布笔记分页 |
| `GET /users/{id}/collections` | 本人或收藏已公开时可读取，仅返回仍然公开的笔记；他人读取私密收藏返回 `403`、`code:collections_private` |
| `PUT /users/{id}/follow` | `{active:true\|false}`；不能关注自己；返回 `followed`、`followedBy`、目标的关注/粉丝数及当前用户的 `viewerFollowingCount` |

| `GET /me/followers` | 本人粉丝公共资料分页 `{items,nextCursor,hasMore}`，`limit` 默认 20、范围 1–50；不接受客户端指定粉丝列表所属账号 |

| `GET /me/notes`、`GET /me/notes/{id}` | 本人管理列表或笔记，含下架状态和处理原因；与普通详情权限分开 |
| `GET /me/collections` | 本人收藏分页，下架或删除笔记不再提供预览 |

| `PATCH /moderation/reports/{id}` | 仅管理员；`{action:'keep'\|'hide'\|'restore',reason,version?,clientMutationId?}`，原因必填，建议携带当前举报版本 |

社区主页资料返回 `followingCount`、`followerCount`、`receivedLikeCount`、`receivedCollectionCount` 和 `receivedEngagementCount`。`receivedEngagementCount` 是当前已发布笔记获赞与收藏的合计；取消互动、删除或下架笔记会改变计数，恢复公开后重新计入。公开资料只提供数量，不包含收藏者身份或他人的私人收藏列表。点击关注或粉丝数量可打开列表弹窗，切换两类关系、搜索并分批加载；关注操作使用服务端确认的关系状态和当前用户关注数更新界面。

举报理由及中文文案统一定义在 `public/community-report-reasons.js`，笔记、主评论和子回复共用同一表单。页面采用单选列表，仅选择 `other` 显示可选说明框；其他选项提交空说明，API 保留可选说明字段以兼容旧客户端。新增理由需要重启服务端进程后生效。

资料另含 `collectionsVisibility`，新旧账号均默认 `private`，修改昵称等其他字段不会重置此设置。每次收藏分页先检查当前可见范围；改回私密时撤销他人的收藏快照，再公开后旧游标也不能复用。既有数据库启动时自动补充字段，导出包含本人设置。

通知 `preview` 可含当前有权查看的关联笔记 `cover`，封面继续经鉴权媒体接口读取。笔记下架、删除或目标评论删除后，撤销普通通知预览及封面；组合分类游标绑定账号及分类，不能与单类型或其他组合混用。

侧栏个人中心和社区“我的”统一使用 `#settings`，主页、收藏、本机草稿使用 `tab` 参数；健康档案、账号与安全、成就墙、AI 服务、阶段复盘和数据管理使用 `section` 参数。账号与安全使用 `section=account`，更换头像依次调用 `POST /api/community/media?purpose=avatar` 与 `PATCH /api/community/me/profile {avatarMediaId}`，不覆盖昵称、简介或收藏设置。旧本人主页链接继续兼容。公开用户页面仅使用社区接口，不渲染私有资料及设置；本人可通过 `?preview=public` 查看对外效果。

### 账号搜索和私信

私信、群消息、评论和回复均可发送文字、图片或图文混合。先调用 `POST /api/community/media?purpose=attachment` 上传图片，再将返回的 ID 放入对应发送请求的 `imageIds` 数组；每条最多 9 张，每张不超过 10 MiB，支持 JPEG、PNG 和静态 WebP。图片不能重复或复用到另一条内容，头像和笔记素材不能直接作为互动附件。文字可为空，但文字和图片不能同时为空。评论与消息 DTO 返回 `images` 数组，文字消息返回空数组。重试应保持同一 `clientMutationId`、图片顺序和正文；改变内容需生成新键。

上传未绑定时仅上传者可预览，七天后到期；绑定后按目标授权。私信图片仅双方可读，群图片仅当前成员且消息晚于其本次入群位置时可读，管理员也不能绕过私密会话权限；所有素材读取别名遵循同样规则。评论图片随评论和笔记的可见状态撤销普通读取，举报管理可查看未删除的原图片。删除评论/笔记、解散群或删除账号时撤销相应图片引用并清理文件。应用壳缓存包含图片交互模块，社区 API 和图片内容继续联网读取。

社区资料新增 `accountNumber`：服务端分配的唯一 10 位公开号码，修改昵称后保持不变。用户搜索忽略大小写、首尾空白和全角字符差异，优先完整账号和完整昵称，再匹配昵称前缀及部分内容；没有发布笔记的已注册用户也可被找到。笔记搜索支持多个以空白分隔的词，标题和话题匹配优先，可切换按发布时间排序。搜索不使用登录邮箱和健康档案。

| 方法和地址 | 请求 / 响应要点 |
| --- | --- |
| `GET /messages/unread` | 本人全部私信与群聊消息合计的 `{unreadCount}`；群邀请另计 |
| `GET /messages/conversations` | `cursor`、`limit`，返回 `{items,nextCursor,hasMore,unreadCount}`，每项含 `id,self,peer,lastMessage,unreadCount,updatedAt`；`self`、`peer` 均为社区公开资料，供展示双方头像及昵称 |
| `POST /messages/conversations` | `{userId}`，建立或复用双方唯一会话，返回 `{conversation}`；拒绝自己和不存在的账号 |
| `GET /messages/conversations/{id}` | 仅参与者读取 `{conversation}`，包含本人 `self` 和对方 `peer` 的社区资料，不包含邮箱或健康档案 |
| `GET /messages/conversations/{id}/messages` | 默认最近 30 条、按发送顺序返回；`before` 读取更早记录，`after` 读取新消息，`after=0` 从第一条开始向前读取，两者不能同时指定；返回 `{items,nextCursor,hasMore}` |
| `POST /messages/conversations/{id}/messages` | `{body?,imageIds?,clientMutationId}`，文字最多 1000 字，文字和图片至少提供一项，返回 `201 {message}`；同一键重试不会重复保存，改内容或会话返回 `409` |
| `PUT /messages/conversations/{id}/read` | `{lastMessageId}`，仅接受本会话收到的消息，将该条及之前收到的消息标为已读；返回 `{unreadCount,conversationUnreadCount}` |

消息 DTO 为 `{id,conversationId,senderId,body,images,createdAt,clientMutationId,sequence}`。`sequence` 是本会话递增序号，避免相同毫秒的消息乱序；游标绑定账号及会话。已读位置只能前进，不会把晚于指定消息的新到达内容清为已读。每账号限制每分钟 60 条、每小时 1000 条发送，新建会话每分钟 60 次，超限返回 `429`。请求读完后再次校验会话和双方账号，防止慢请求继续给已注销账号写入消息。

私信与 AI 会话数据独立，管理员身份也不提供查看他人私信的权限。数据导出包括 `community.privateMessages.conversations` 及各会话消息；注销任一参与者会清理双方对应会话及消息。前端按账号保存最近搜索、未发送文字和已上传的图片草稿元数据，注销当前账号时清理当前浏览器中的这些数据。

### 群聊、管理员与提醒

下列地址均以 `/api/community` 为前缀，要求登录。消息页的“私信”和“群聊”分开展示；群号为服务端分配的唯一 8 位号码，群人数上限 100 人。外部用户只能通过完整群号查找群名称、简介及人数，申请经群主或管理员批准后加入，收到邀请的用户需自行接受。创建群和加入群按钮仅在群聊页展示，私信列表与私信会话不展示。邀请弹窗可切换“搜索用户”和“我的粉丝”，两种来源共用勾选结果，每次最多邀请 20 人；已在群内的用户不可重复选择。群成员管理支持按昵称或循序号本地搜索已加载成员、清空与无匹配提示，点击头像关闭弹窗并进入成员主页；自己进入个人中心。成员筛选不改变后端管理权限与成员 ID。

| 方法和地址 | 请求 / 响应要点 |
| --- | --- |
| `GET /groups`、`POST /groups` | 读取本人群列表；创建提交 `{name,description,announcement,clientMutationId}`，返回 `{group}` |
| `GET /groups/search?q=群号` | 完整群号查询，返回 `{items}`，不包含成员、公告及聊天记录 |
| `GET /groups/unread` | `{unreadCount,mentionUnreadCount,invitationCount}`，仅统计群消息及群邀请 |
| `GET /groups/invitations` | 本人待处理群邀请，支持 `cursor`、`limit` |
| `PATCH /groups/invitations/{id}` | `{action:'accept'\|'decline'}`，接受后返回群资料 |
| `GET /groups/{id}`、`PATCH /groups/{id}` | 成员读取资料；群主或管理员修改 `name,description,announcement,muteAll` |
| `GET /groups/{id}/members` | 成员名单，支持 `cursor`、`limit` |
| `PATCH /groups/{id}/members/{userId}` | `{role:'admin'\|'member',muted:true\|false}`；仅群主任免管理员，管理员只能禁言普通成员 |
| `DELETE /groups/{id}/members/{userId}` | 群主移除管理员或普通成员，管理员只能移除普通成员；提交空 JSON 对象 |
| `POST /groups/{id}/join` | 提交空 JSON 对象申请入群，重复申请复用当前待处理记录 |
| `GET /groups/{id}/requests`、`PATCH /groups/{id}/requests/{requestId}` | 群主或管理员读取申请并提交 `{action:'approve'\|'reject'}`；列表支持分页 |
| `POST /groups/{id}/invitations` | 群成员提交 `{userIds:[...]}`，每批 1–20 人，逐个等待接受 |
| `GET /groups/{id}/messages` | 默认最近 30 条，可用 `before`、`after` 读取历史或新增消息；返回 `{items,nextCursor,hasMore}` |
| `POST /groups/{id}/messages` | `{body?,imageIds?,clientMutationId,mentionUserIds,mentionAll}`，文字和图片至少一项，正文最多 1000 字，每条最多指定 20 位当前成员；仅群主或管理员可 `@全体成员` |
| `PUT /groups/{id}/read` | `{lastMessageId}`，只能标记已从消息接口收到且属于本次入群的他人消息；返回群总未读、提醒未读及当前群未读 |
| `POST /groups/{id}/leave` | 提交空 JSON 对象退出；群主需先转让或解散 |
| `POST /groups/{id}/transfer` | 群主提交 `{userId}` 转让给现有成员；新群主解除个人禁言 |
| `DELETE /groups/{id}` | 仅群主解散，提交空 JSON 对象 |

单人禁言与全员禁言均由服务端校验，全员禁言时群主和管理员可发言。`@` 使用结构化成员 ID 保存，群列表展示“有人@我”，阅读相应消息后清除提醒；自己的消息不增加未读。顶部消息图标统计私信与群聊的消息合计，读取一种会话不会清除另一种会话的未读。新建群、邀请和发送均有限流，发送失败可按原 `clientMutationId` 重试而不重复入库。

消息、成员和资料只向当前群成员开放；社区举报管理员身份不提供群聊访问权限。所有写入在读完请求后重新检查成员身份和管理权限。退出、被移除或解散立即撤销访问；重新加入后仅能读取本次入群之后的消息，分页游标绑定账号、群及本次成员记录。群消息不进入公开互动通知。

`GET /me/followers` 只读取会话账号自己的粉丝：粉丝是关注当前账号的用户，返回公开昵称、公开账号、头像、简介和当前关注状态，不返回邮箱或健康数据。分页快照和游标绑定登录账号；继续加载时会重新检查关注关系及账号是否仍存在，跳过取消关注或注销的用户。粉丝选项仍提交原群邀请接口，对方接受前不会获得群访问权限。

账号导出包含 `community.groups` 下的本人群资料、本人发送的消息、本人邀请和申请。注销会删除本人发送的消息，保留其他成员消息；群主注销时优先交接给管理员或最早加入的成员，无其他成员则解散。群文字草稿、提醒对象和失败发送记录按账号保存，清理账号数据时一并移除。

笔记、评论、作者笔记、收藏、通知和管理列表支持 `limit`（默认 20，范围 1–50）及 `cursor`，返回 `{items,nextCursor,hasMore}`。分页使用绑定当前账号与查询条件的排序快照，有效期 30 分钟；过期返回 `409`，改用其他账号或筛选条件时不能复用游标。后续翻页仍重新检查内容可见性，快照不会继续暴露已经下架、删除或不再符合关注条件的内容。

标题必填，最多 40 字；正文最多 2000 字，纯文字笔记正文不能为空。分类使用 `training`、`diet`、`checkin`、`experience`、`question`；最多五个话题，每个最多 20 字。`type` 为 `text`、`image` 或 `video`，`media` 条目为 `{id,role,isCover}`；图文使用 `role:'image'`、最多九张，视频使用一个 `role:'video'` 和一个 `role:'video-cover'`，独立图片封面设为 `isCover:true`。也可用 `coverMediaId` 指定本篇图片封面。仅允许 `visibility:'members'`，不得混用图文和视频。服务端校验所有素材属于当前作者、用途正确、仍有效且未绑定其他笔记。

评论最多 500 字，社区昵称最多 20 字、简介最多 120 字，举报说明和处理原因最多 500 字。发布笔记、发布评论和举报要求 `clientMutationId`，长度 1–100，只允许字母、数字、下划线、冒号和连字符；相同操作与相同内容重试返回已确认结果，相同键用于不同内容返回 `409`。点赞、收藏和关注使用明确的 `active` 状态，同一事务更新关系、计数和通知，并排除自己操作产生的通知。

笔记、评论、关注和举报分别限制为每账号 20 次/小时、60 次/10 分钟、100 次/小时和 20 次/小时，超限返回 `429` 及 `Retry-After`。隐藏内容不再经普通详情、媒体、收藏和通知预览读取；作者使用本人管理接口，管理员使用处理队列和管理媒体接口。作者修改下架笔记后仍保持下架，需管理员选择恢复。

### 社区媒体

| 方法和地址 | 请求 / 响应要点 |
| --- | --- |
| `POST /api/community/media?purpose=note` | 原始文件二进制请求体，设置真实 `Content-Type`、URL 编码的 `X-Filename` 与 `X-Fitness-User`；返回 `201 {media}` |
| `POST /api/community/media?purpose=avatar` | 独立头像用途，仅接受图片，不能直接作为笔记素材 |
| `POST /api/community/media?purpose=attachment` | 评论/回复/私信/群消息的独立图片用途，上传后通过发送请求的 `imageIds` 绑定；普通 GET 根据绑定内容检查可见权限 |
| `GET /api/community/media/{id}`、`HEAD /api/community/media/{id}` | 本人未发布有效素材、有效社区头像或已发布笔记媒体的授权读取；支持 Range |
| `GET /api/community/media/{id}/metadata` | 仅本人查询 `{media}`，包括 `status`、`expiresAt`、尺寸及视频时长；未引用过期素材返回 `410` |
| `DELETE /api/community/media/{id}` | 本人清理未引用素材；仍被笔记或头像引用时返回 `409` |
| `GET /api/community/me/media/{id}`、`HEAD /api/community/me/media/{id}` | 本人管理媒体，包括自己下架笔记的素材 |
| `GET /api/community/moderation/media/{id}`、`HEAD /api/community/moderation/media/{id}` | 管理员经处理队列读取笔记素材；已删除内容仍不可读 |

图片只接受 JPEG、PNG、WebP，每张最大 `10 MiB`；拒绝 SVG、HTML、GIF 和伪造格式。短视频最大 `50 MiB`、最长 60 秒，只接受完整的非分片 MP4：一个 H.264 `avc1` 视频轨，Baseline/Main/High、8 位、4:2:0，及可选的一个 AAC-LC 音频轨。HEVC、AV1、分片 MP4 或其他编码会被拒绝；首期不自动转码，需用户提供独立图片封面。服务端校验真实文件结构、图片尺寸、编码和视频时长，不只依赖扩展名或浏览器元信息。

WebP 在结构与尺寸检查后，使用随项目提供的 libwebp WASM 实际解码；损坏的压缩图像数据返回 `422`，不保存为可发布素材。部署时须保留 `server/community-webp.mjs` 和 `server/vendor/libwebp/` 中的二进制及许可文件，无需额外安装运行依赖。

媒体 DTO 包含 `id`、`purpose`、MIME `type`、`size`、`width`、`height`、`duration`、`status`、`createdAt`、`expiresAt` 和鉴权 `url`。素材先以独立文件上传，笔记提交只传素材 ID，不将视频塞入 JSON、SQLite BLOB 或健康记录。每账号社区媒体总容量为 `250 MiB`，独立于私有附件额度；每分钟最多 12 次上传。容量或频率超限返回 `429`，文件超限返回 `413`。

未引用素材七天后到期并由启动、定时及上传前清理回收；发布笔记或保存头像后解除到期时间，编辑移除的素材和旧头像重新计入七天到期。每份笔记素材只能绑定一篇笔记。删除笔记立即取消读取并回收文件，下架只撤销普通社区读取、保留本人和管理员处理权限。下载使用 `Cache-Control: no-store`；视频有效单段 Range 返回 `206` 和 `Content-Range`，无效或越界范围返回 `416`。

### 同步与容量

最多配置 20 个供应商，每商最多启用 500 个模型。`tasks` 与 `taskModels` 分开保存，因此同一家供应商的不同模型可分别承担对话、餐食和规划。省略任务映射时尽量保留仍有效的原选择；旧版只提交单个 `model` 的调用方式继续兼容。更换供应商预设、协议或接口地址时，已有密钥不会自动发往新目标，必须重新提供密钥或显式清除。

记录 ID 在一个账号内唯一，允许字母、数字、下划线、连字符、冒号，长度最多 `100`。`kind` 最多 `40` 字符。未删除记录的 `data` 必须为 JSON 对象；服务端保留业务结构的灵活性，不对客户端传入的健康资料作医学真实性校验。

新记录使用 `baseVersion:0`。已存在的记录必须携带服务端最新版本；更新成功后版本加一。版本不匹配不会覆盖服务端内容，`conflicts` 中返回 `{id,server}`，其他无冲突记录仍会保存。删除也增加版本并留下墓碑，防止旧设备把已删除内容重新同步回来。客户端应始终发送 `userId`，防止另一标签页切换账号后误把旧离线队列写入新账号。

每次同步最多 `500` 条、请求体最多 `8 MB`。单个会话记录最多 `2 MB`，其他记录最多 `256 KB`。超过限制应拆分同步批次，或新建会话；服务端返回明确的 `413`，不会静默截断用户记录。

单个上传附件最多 `8 MB`，每用户附件总量最多 `250 MB`。支持 JPEG、PNG、WebP、GIF、PDF 和四种文本格式；不接收 SVG/HTML。每条 AI 消息最多 `6` 个附件，每次 AI 请求附件合计最多 `24 MB`。AI 请求最多 `80` 条用户/助手消息，单条文本最多 `32000` 字符，单条助手 `reasoningContent` 最多 `64000` 字符，上下文最多 `256000` 字符。浏览器应保存完整历史，仅发送近期消息。服务端不接收客户端自定义的 system 消息。

删除会话或餐食等记录时，服务端会清空墓碑中的原文，并回收该记录原来引用、且其它有效记录不再引用的附件。编辑已有记录时移除照片，也会在同步后回收已失去全部有效引用的附件。仍被其它记录共享的图片继续保留。刚上传而尚未存入任何记录的附件不会受这种清理影响。

取消上传后，可调用附件 DELETE 接口清理未引用文件；服务端不会定时扫描删除全部孤立附件，因为离线草稿可能尚未同步引用。账号删除会清理所有附件，包括没有被记录引用的文件。
