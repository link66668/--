# 循序社区功能设计

版本：V1.12
日期：2026 年 10 月 3 日  
状态：第一期已实施，补充群聊、群管理员、禁言、@ 提醒、粉丝邀请、成员搜索及私信/群聊/评论图片，第二期规划保留
适用项目：循序 · AI 健身助手

本方案参考用户提供的小红书桌面发现页、笔记详情弹层和手机发现页，设计一个围绕训练、饮食和日常进步的社区。主要体验是图片优先的瀑布流、便于连续浏览的笔记详情，以及发布、点赞、收藏、评论和关注形成的互动流程。第一期已按本方案接入现有应用，V1.2 补充按昵称及公开账号找人和双人私信；V1.12 增加私信、群聊、评论与回复图片。文档保留页面布局、操作规则、数据边界和验收条件；第二期与后续扩展仍属于规划。

## 产品目标和功能范围

社区帮助用户发现可实践的经验，分享一次训练、一份餐食或一段进步，并通过互动持续参与。典型内容包括“今天完成了第一次完整训练”“工作日的便当准备”“深蹲练习记录”和“连续坚持四周的感受”。

第一期社区位于登录后的应用中。发布内容默认向同一服务中的所有已登录社区用户展示；发布前明确提示这一范围。站外打开分享链接时，先登录，再返回对应笔记。访客直接浏览放在后续阶段，避免把当前仅供登录用户使用的应用外壳隐式改成公开网站。

| 阶段 | 功能 | 完成标准 |
| --- | --- | --- |
| 第一期（已实现） | 推荐和关注信息流、分类筛选、笔记与账号搜索、图文和短视频、详情、评论及回复、点赞收藏、关注、作者主页、我的笔记与草稿、互动通知、双人私信、群聊及群管理、举报及基础处理；私信、群消息、评论及回复均支持文字和最多九张图片 | 用户可独立完成浏览、发布、互动、联系其他账号和管理自己内容的完整流程 |
| 第二期（规划） | 话题搜索、话题聚合、访客浏览、收藏夹、训练和餐食分享卡片、媒体转码和更完善的管理页面 | 提高内容发现效率，并连接个人记录与社区 |
| 后续扩展 | 打卡活动、专题精选、进步分享卡片、个性化推荐 | 在有实际内容和参与数据后逐步扩展 |

直播、商城和商业合作不属于本次设计范围。根据补充需求，本期加入已登录用户之间的文字和图片私信；通知中心展示社区互动，消息页分为私信与群聊，支持群主与管理员管理成员、单人和全员禁言、@ 提醒及入群审批，“AI 对话”继续承载原有 AI 会话。

群聊采用左侧群列表、右侧聊天的桌面布局，手机在列表与会话间切换。“创建群”“加入群”仅出现在群聊页，私信列表和会话隐藏这两个按钮。邀请群成员支持搜索社区用户或切换“我的粉丝”直接勾选，切换来源保留已选成员，每次最多 20 人；已有群成员显示“已在群内”，对方接受邀请后才加入。粉丝列表按真实关注关系分页，仅返回本人粉丝的公开资料。群资料与管理的“成员”页支持按昵称或循序号即时筛选、清空及无匹配提示；成员头像可点击查看主页，本人进入个人中心。筛选只改变显示结果，任免、禁言及移除继续操作真实成员 ID，管理刷新后保留搜索条件。创建后分配唯一 8 位群号；加入需申请获批或接受邀请。群主可任免管理员、转让和解散，管理员可发布公告、审批入群、禁言和移除普通成员。聊天的“@ 提醒”可选当前成员，群主与管理员另可选择全体成员。群列表标明“有人@我”，未读合并到顶部消息提醒；收到的消息显示提醒对象。单人及全员禁言由服务端执行，退出或移除后立即失去访问权限。当前支持文字、图片及图文混合群消息，每条最多九张图片；通用文件、语音与视频群消息保留给后续扩展。

## 信息架构和访问路径

桌面主导航增加“社区”，放在“知识大全”与“个人中心”之间。社区内部设置“推荐”“关注”“我的”三个一级标签；搜索框、消息、通知入口和“发布笔记”按钮位于社区顶部。

```text
社区
├─ 推荐
│  ├─ 全部 / 训练 / 饮食 / 打卡 / 经验 / 提问
│  ├─ 搜索结果
│  └─ 笔记详情
├─ 关注
│  └─ 已关注作者的笔记
├─ 我的
│  ├─ 已发布
│  ├─ 已收藏
│  └─ 草稿
├─ 作者主页
├─ 发布和编辑笔记
├─ 消息
│  ├─ 私信会话
│  └─ 群聊：创建 / 申请 / 邀请 / 公告 / 成员与权限
└─ 互动通知
   ├─ 赞与收藏
   ├─ 评论与回复
   ├─ 新增关注
   └─ 内容处理结果
```

社区使用 hash 路径接入当前单页应用，路径约定如下。过滤条件可以带在 hash 中的查询参数内。

| 路径 | 页面 |
| --- | --- |
| `#community` | 推荐信息流 |
| `#community/following` | 关注信息流 |
| `#community/search?q=关键词&type=notes\|users` | 笔记或用户搜索结果；笔记支持 `sort=relevance\|latest` |
| `#community/messages` | 消息入口，默认私信，可切换群聊 |
| `#community/messages/groups` | 本人群聊列表，创建群、群号申请加入及群邀请 |
| `#community/messages/group/{id}` | 群聊天、公告、成员管理、管理员与禁言 |
| `#community/messages/{id}` | 本人参与的双人会话 |
| `#community/note/{noteId}` | 笔记详情及可复制的分享地址 |
| `#community/user/{userId}` | 他人的公开主页；本人链接归入个人中心 |
| `#community/user/{本人的userId}?preview=public` | 查看自己对外展示的公开主页 |
| `#settings`、`#settings?tab=published\|collections\|drafts` | 统一个人中心中的主页、笔记、收藏及本机草稿 |
| `#settings?section=profile\|achievements\|ai\|review\|data` | 本人的健康档案、成就墙、AI 服务、阶段复盘和数据管理 |
| `#community/mine?tab=published\|collections\|drafts` | 兼容旧链接，归入统一个人中心对应标签 |
| `#community/publish` | 发布笔记 |
| `#community/edit/{noteId}` | 编辑自己的笔记 |
| `#community/notifications` | 互动通知 |

社区路由与应用内的 `state.page` 页面状态协作，并处理浏览器前进后退。浏览器刷新、直接打开笔记链接和登录完成后均应恢复目标页面，必要的首次建档弹窗关闭后继续返回该目标。

社区顶部工具区和分类条在滚动时吸顶。当前应用顶部栏随页面滚出后，社区工具区贴近视口顶部，不为已离开的顶部栏继续预留空白。搜索框可伸缩，发布按钮保持可见；较窄宽度下将完整搜索框收为搜索入口。

瀑布流列数根据实际内容容器宽度计算，而非只看窗口宽度，确保侧栏展开和收起后都合理。桌面列间距建议 20px，最小卡片宽度建议 224px，最多五列。

| 信息流容器宽度 | 列数 | 场景 |
| --- | --- | --- |
| 1200px 及以上 | 5 | 宽屏桌面 |
| 956 至 1199px | 4 | 常规桌面 |
| 712 至 955px | 3 | 较窄桌面或平板 |
| 468 至 711px | 2 | 小窗口或平板 |
| 468px 以下 | 2 | 手机；使用更紧凑的间距和字体 |

每次取回 20 条笔记，接近列表底部时加载下一批，同时提供“加载更多”按钮。列表末尾区分“加载中”“加载失败，点击重试”和“已经看完了”。第一屏使用保持封面比例的骨架占位。

## 笔记卡片和内容类型

卡片采用“封面 → 标题 → 作者和点赞”的信息顺序。卡片外层不加粗边框和明显阴影，封面使用 14 至 16px 圆角；标题最多两行，正文不在信息流中完整展开。

| 元素 | 设计和交互 |
| --- | --- |
| 封面 | 优先显示原图比例，信息流展示比例限制在宽高比 3:4 至 4:3 之间，超出部分适度裁切，详情查看完整内容 |
| 多图标记 | 封面右上角展示图片数量，例如“3 图” |
| 视频标记 | 封面右上角显示播放图标和时长，信息流中不自动播放 |
| 标题 | 桌面建议 15px，手机建议 14px，约 1.5 倍行高，最多两行 |
| 作者 | 24px 圆形头像加昵称；过长昵称省略，点击单独进入作者主页 |
| 点赞 | 空心图标和数量；点按切换选中状态，不触发详情打开 |
| 内容说明 | 分享卡片使用“训练记录”“餐食分享”等短标记，区分内容来源 |

纯文字笔记生成简洁的文字封面，使用短标题和正文摘要，背景可选择灰紫、浅蓝或米白；封面不把长文缩成难读的小字。整张封面和标题可打开详情，作者及点赞是独立操作目标，不能嵌套成互相抢点击的按钮。

推荐页首先提供健身内容的分类选择；首期笔记只能选择一个主分类，可以另选最多五个话题。用户手动搜索后进入独立结果页，保留关键词；空结果提供清除筛选或换词入口。

首期推荐采用明确的服务端规则：近期互动较多的内容与新发布内容混排，优先保证内容多样性；关注页和作者主页按发布时间倒序。每轮浏览生成固定排序快照，点赞和新笔记不会让已加载卡片重新排序。只有可见、未删除和未下架的内容参与列表。

## 笔记详情

### 桌面布局

在信息流上打开居中的双栏弹层，背景使用约 45% 的深色遮罩。弹层宽度建议不超过 1200px，高度不超过视口的 90%，媒体和内容区域比例约为 55:45，内容栏宽度不低于 360px。空间不足时使用下文的单栏详情布局。

```text
┌────────────────────────────┬──────────────────────────┐
│                            │ 头像 昵称         关注    │
│                            │                          │
│        图片轮播            │ 标题                     │
│           或               │ 正文及话题               │
│        视频播放器          │ 发布时间       更多       │
│                            │ ──────────────────────── │
│                            │ 评论数量  最新 / 热门     │
│                            │ 评论及最多一级回复        │
│                            │ 正文和评论共同滚动        │
│        1 / 3               ├──────────────────────────┤
│                            │ 写评论…  ♡  ☆  评论  分享 │
└────────────────────────────┴──────────────────────────┘
```

媒体区使用 `contain` 展示完整图片，背景使用接近黑色或浅灰的纯色，避免拉伸。多图支持左右切换、序号、键盘方向键和点击放大。视频提供播放暂停、进度、音量和全屏；进入详情显示封面，用户点击后开始播放，关闭弹层即停止播放。

右栏顶部是作者信息和关注按钮，下方依次为标题、正文、话题、发布时间及评论。正文和评论共同处于右栏滚动区域，底部评论入口及互动栏固定；未编辑时输入区和互动按钮同排，聚焦、输入或回复时展开输入区。长正文可以折叠为“展开全文”，不挤走评论入口。

主评论头像与昵称顶部对齐，子回复缩进并使用较小头像。笔记和每条可见评论、回复右侧的省略号展开就地操作菜单；菜单采用白底圆角和轻阴影，外点击或 Escape 关闭，键盘可以选择操作。点击举报后打开原因和补充说明表单。

关闭按钮始终可见。支持 Esc、遮罩点击和浏览器返回关闭；关闭后恢复原筛选、已加载笔记和滚动位置，键盘焦点回到原卡片。直接通过链接进入详情时，关闭后回到社区推荐页。已输入但未发送的评论在当前账号、当前笔记下保留。

### 手机布局

手机详情使用占满视口的单栏页面，顶部固定“返回”，主体依次展示媒体、作者、正文和评论。笔记“更多”位于日期右侧，评论操作位于昵称右侧。媒体完整显示，图片横滑切换，底部展示序号。

底部固定“写评论”输入入口及点赞、收藏、评论、分享。打开键盘时，输入区跟随可见视口上移；正文底部预留操作栏和系统安全区高度，最后一条评论能够完整滚到可视位置。返回时恢复实际来源页面及其原位置，包括推荐、关注、搜索、作者主页、收藏或通知；直接链接进入时回到推荐页。

### 互动规则

| 操作 | 规则 |
| --- | --- |
| 点赞和收藏 | 使用明确的目标状态提交；成功时更新卡片和详情，失败时恢复原状态并提示重试 |
| 关注 | 展示“关注 / 已关注”，本人主页与本人笔记隐藏关注按钮；取消关注同步更新关注信息流 |
| 评论 | 文本上限 500 字，可附最多 9 张图片或只发图片；提交时防止重复发送；默认最新排序，可切换热门；每页 20 条 |
| 回复 | 最多展示一级回复；回复某条回复时标注“回复某某”，所有回复归于对应顶层评论；初始展示 1 条，提供“展开 N 条回复”和“收起回复”，展开继续分页且收起保留缓存；发送及通知定位自动展开目标线程 |
| 评论点赞 | 独立计数，同一账号同一评论最多一次；取消操作可以重复执行 |
| 删除评论 | 作者可以删除自己的评论；笔记作者可删除其笔记下的评论；删除后保留必要的回复上下文占位 |
| 更多 | 自己的笔记显示编辑和删除；其他人的笔记及主评论、子回复均提供举报；操作菜单在省略号附近展开，评论删除按上述权限展示 |
| 分享 | 优先使用设备分享入口，不支持时复制本站笔记地址并提示“链接已复制” |

删除笔记需要确认，删除后从发现、搜索、作者主页和收藏列表移除。已打开该内容的用户再次操作时得到“笔记已删除或不可见”，不会继续得到成功反馈。删除顶层评论后，有回复时显示“评论已删除”，没有回复时移除整条；可见评论总数按未删除的顶层评论和回复合计。

## 手机发现页

私信、群聊及评论输入区提供“添加图片”，共用最多 9 张、每张 10 MiB 的 JPEG/PNG/静态 WebP 校验。选择后展示缩略图、上传进度、移除和失败重试；上传完成后可以只发图片，也可和正文一起发送，回复沿用评论图片能力。消息和评论显示图片缩略图，点击进入大图并可切换同条内容的图片。上传失败和发送失败保留当前草稿；发送确认只移除已发送图片，保留期间新增图片和文字。图片未上传完成或存在失败素材时阻止提交，群禁言规则同样适用于图片。

互动图片使用独立用途和 `community_attachment_media` 绑定表。未绑定图片仅本人预览，绑定后按评论、私信或群消息权限读取；管理员身份不能读取未参与的私信和群聊图片。群历史图片也遵循本次入群位置，退出或被移除后立即失去读取权限。评论隐藏、内容删除和账号清理同时撤销相应图片可见性；删除清理覆盖其他发送者在被删除内容下的附件。既有数据库保留笔记及头像引用并自动迁移用途约束。

以 390px 宽度为基准：左右留白 16px，两列间距 12px，单卡片宽约 173px。320 至 360px 使用 12px 留白和 10px 间距，仍保持两列；更窄的视口或高倍缩放允许降为一列。

进入搜索时显示专用搜索栏、取消按钮和结果，键盘回车触发查询；不在输入每个字时强制刷新页面。参考图中的直播、视频频道和六项底部导航不直接移植到本期应用。

## 搜索账号和笔记

搜索输入最多 100 字，回车或点击搜索提交。只输入空白时留在当前页并提示输入关键词；输入过程不触发请求。提供清空输入和取消搜索入口；手机端可点击“取消”、点击搜索栏外部或按 Escape 收起搜索，保留未提交内容及当前页面，取消后焦点返回搜索入口。搜索保留“搜索笔记、昵称或循序号”原提示和完整可读标签。最近八条搜索按当前登录账号保存在本机，可以清除，切换账号时不会显示其他账号的历史。

结果页保留关键词，提供“笔记”“用户”两个标签。笔记搜索标题、正文和话题，默认按相关程度排序，可切换“最新”，继续使用分类筛选。切换标签保留关键词；用户结果不展示笔记分类。昵称匹配忽略大小写及首尾空白，固定公开账号用于精确定位，完整账号和完整昵称优先于部分匹配。昵称重名时通过头像和循序号区分；没有发布过笔记的已注册账号也能被找到。

用户搜索采用白底横向列表：左侧圆形头像，中间为昵称、循序号及真实粉丝和笔记数量，右侧为独立的关注按钮。头像和资料点击进入主页，关注操作保持在结果页；成功后同步关注状态和粉丝数量，请求期间禁用重复提交，失败可重试。自己的结果显示“我”，不显示关注按钮。分页追加结果时保留已确认的关注状态；没有真实更新时间时不展示更新时间标签。

公开账号是服务端生成并保存的唯一 10 位号码，不随昵称修改而变化。搜索不使用登录邮箱、密码或健康档案作为匹配条件，结果只包含社区公开资料。空结果说明当前查找的是笔记还是用户，并提供换词或切换类型的入口；请求失败保留输入，允许重试。

## 双人私信

社区顶部提供“私信”入口和未读提醒。自己的主页不显示向自己发送私信的按钮；服务端也拒绝建立自己的会话。双方只维护一个会话，从主页反复点击私信会返回原会话。会话列表按最近消息排序，显示对方头像、昵称、最后一条消息、时间和未读数量，进入会话后可核对公开账号；没有发送记录时显示开始聊天提示。

消息页参考双栏消息中心：白底左栏顶部显示“消息”和“返回首页”，下面为可独立滚动的会话列表；右栏未选择会话时显示“点击消息开启会话”，选择后展示真实聊天。桌面保留会话列表及选中状态，手机采用列表、会话和返回列表的单栏流程。聊天头部同时提供“返回首页”，手机另保留返回会话列表按钮。消息页隐藏社区工具栏，首页指社区推荐页 `#community`，返回后恢复工具栏。聊天内容独立滚动，输入区保持可见；会话列表更新保留未变化的节点、滚动位置及已确认的未读状态。

会话页面展示双方文字消息，单条最多 1000 字。Enter 发送，Shift+Enter 换行，中文输入法组词期间不发送。发送期间显示状态，失败保留文字并提供重试，同一条消息的重试沿用请求唯一键以防重复。未发送内容按登录账号和会话保存在本机，返回页面时恢复。最新消息在底部，加载更早消息保留阅读位置，用户查看旧消息时新消息不会强行拉到底部。

页面可见且仍位于社区时定期刷新会话和未读数量，离开页面、切换账号或后台隐藏时停止刷新。读取会话只把已经加载并展示的消息标为已读，不把同时到达但尚未展示的新消息一起清除；旧未读请求延迟返回时不能覆盖已确认的已读状态。没有新消息的轮询保留聊天节点和文字选择。首次加载失败可重新加载，即使期间已发送新消息，重试仍能取回历史记录。桌面和手机均在消息列表内部滚动，输入区保持可见，长消息自动换行。

私信与 AI 对话、健康同步记录及互动通知使用独立数据表和接口。只有当前会话的两个参与者可读写；不能通过修改 URL、请求体或账号头读取第三人的消息。账号数据导出包含本人参与的私信，注销账号清理涉及该账号的会话和消息。本期仅支持文字，其他消息类型另行设计。

## 发布与编辑

发布页采用独立页面，桌面为“素材预览 + 内容表单”两栏，手机为纵向表单。顶部提供返回及草稿状态，底部提供“存为草稿”“预览”“发布”。

| 字段 | 首期约定 |
| --- | --- |
| 类型 | 图文或短视频，纯文字按图文处理 |
| 图片 | 0 至 9 张，JPEG、PNG 或 WebP，每张原文件不超过 10MB；有图片时可排序并指定封面 |
| 视频 | 1 个 MP4，最长 60 秒、最大 50MB；另选一张封面，使用独立上传通道 |
| 标题 | 必填，1 至 40 字 |
| 正文 | 最多 2000 字，保留换行，纯文字笔记必须填写正文 |
| 主分类 | 必选，训练、饮食、打卡、经验或提问 |
| 话题 | 最多 5 个，每个最多 20 字，可选，不把普通正文中的每个井号自动变成话题 |
| 可见范围 | 固定显示“所有已登录社区用户可见”，首期不提供模糊的公开或私密开关 |

素材需显示上传进度、失败原因和重试入口。用户可在文字编辑期间上传素材，全部上传并通过验证后才能发布；发布期间按钮进入忙碌状态，重复点击和网络重试不能创建重复笔记。

草稿文字、素材顺序和封面选择按账号保存在本机 IndexedDB，切换页面时自动保存；草稿明确显示“仅保存在本机”。二进制素材的本地保存受浏览器容量限制，保存失败时提示重新选择素材，不能显示虚假的“已保存”。已经上传的草稿素材仍仅对本人可见，成功发布后才转为社区可读。

文字保存、本机素材保存和服务端素材上传分别记录状态。建议未引用的服务端素材保留七天，上传响应返回到期时间；重开草稿时验证媒体状态，已过期但本机仍有文件时可重新上传，本机也无文件时提示重新选择。上传成功不代表素材永久保存，发布前必须重新确认所有素材仍有效。

离线时可继续编辑草稿，点赞、评论、关注和发布提示需要联网，不自动排队发送。登录失效时保留当前草稿和原访问目标，重新登录同一账号后继续操作。退出登录或切换账号后，界面不得展示上一个账号的草稿。

编辑自己的已发布笔记沿用发布表单，保存时校验服务端版本；多端发生冲突时提示重新读取并保留本地修改。修改影响内容及更新时间，原发布时间、互动关系和笔记地址保持不变。取消编辑不修改线上内容。编辑下架笔记仍保持下架状态，只有管理员恢复后才能重新展示，用户不能通过修改或重新提交同一笔记绕过处理结果。

## 作者主页和通知

个人主页参考新增截图，采用白色页面、大圆形头像和宽松的资料区。桌面头像在左，昵称、固定的 10 位循序号及可换行简介居中，操作区在右上；资料下方横排显示关注、粉丝和“获赞与收藏”。主操作延续循序的蓝色。手机缩小头像，资料和操作区按可用宽度排列，不裁切昵称、简介和统计。

自己的社区主页并入综合“个人中心”，侧栏“个人中心”和社区“我的”均进入 `#settings`，不再维护第二个本人页面。内部栏目包括我的主页、健康档案、成就墙、AI 服务、阶段复盘、数据与同步。主页提供资料编辑、发布笔记和“他人视角”入口；公开预览只展示社区资料及可公开内容，隐藏管理和草稿入口。资料保存后立即更新当前头部。他人的主页提供关注按钮和圆形私信图标，关注后立即更新目标粉丝数；更多图标打开公开主页分享链接。点击私信打开双方已有会话，没有会话时建立一个空会话。

资料区下方居中排列胶囊标签“笔记”“收藏”，自己的主页另外提供“草稿”。笔记沿用瀑布流，自己的管理页面继续显示本人可管理的下架内容；他人只能查看已公开笔记。收藏可由本人选择“仅自己可见”或“社区用户可见”，新旧账号默认私密。可见范围统一在“编辑资料”中保存，收藏标签内直接展示收藏内容，不显示独立设置栏。公开后他人可查看仍然公开的收藏笔记；私密时标签带锁，点击显示隐私说明。服务端在每次分页前检查权限，切回私密时撤销他人的列表快照，旧游标不能继续读取。草稿和未知标签参数不能让他人主页读取当前登录用户的私有内容。

“获赞与收藏”合计该作者当前已公开笔记收到的点赞和收藏。下架或删除笔记不计入，取消互动后实时减去；统计不包含收藏者名单、本人收藏了多少笔记或其他健康数据。

同一主页的“笔记／收藏／草稿”切换保留头像、资料区和标签节点，选中胶囊用 300ms 平移衔接，下方内容以 90ms 淡出、220ms 淡入及轻微横向位移切换，方向随标签顺序变化。加载及瀑布流测量期间保持旧内容区高度和隐藏状态，避免页面先缩短再变长或内容二次闪现。新内容允许时保持滚动位置；长列表切到短列表时，在布局稳定后用约 200ms 将位置平滑调整到新的合法范围，再释放高度。连续点击同一标签不打断当前加载，快速跨标签切换取消旧动画并忽略过期响应。他人收藏仍先检查可见范围，再展示列表或缓存；系统选择减少动态效果时直接切换。

社区资料独立于健康档案。首次启用时使用已有称呼作为可编辑昵称，默认采用首字头像；后续可上传头像和填写简介，昵称上限 20 字，简介上限 120 字。本人在统一中心可管理健康与账号资料，邮箱、年龄、身高、当前体重、营养目标、完整训练日历和 AI 服务配置始终不出现在公开主页。公开收藏只开放收藏笔记，不开放其他私有数据；本机草稿始终仅本人可见。

通知铃铛显示所有互动类型合计的未读数量，零未读时隐藏数字角标，超过 99 显示“99+”；无障碍标签保留完整数量。标记指定通知或全部已读后同步更新角标，读取失败时保留原数。列表按最新事件排序，支持按类型筛选和“全部已读”。点击某条通知后才将其标为已读，并跳到对应笔记或评论；打开通知中心不会自动清空全部未读。

社区页面可见时每 5 秒轮询互动通知总数，恢复前台时立即刷新；离开社区、销毁页面或切换账号后停止。重复刷新合并为一份在途请求，慢请求或失败不阻塞私信与群聊轮询。已读操作完成后，迟到的旧通知读数不能恢复已清除的角标；必要时重新读取当前权威数量。

通知页采用白底宽列表，隐藏顶部社区工具栏和浮动发布入口，在页内提供“返回首页”和“全部已读”。三个主胶囊为“评论和回复”“赞和收藏”“新增关注”，保留“全部通知”和“处理结果”辅助入口。每行展示头像、昵称、互动说明与日期、正文及右侧笔记封面，文字笔记使用文字小卡；内容不可见时撤销预览。组合分类在服务端分页前筛选，不能只筛选当前页。当前未实现账号提及，因此不展示未支持的“@”分类承诺。

首期每个用户、目标和互动类型只保留一条有效通知记录，重新点赞、收藏或关注更新原记录，不反复产生未读提醒；评论和回复按评论 ID 去重。自己的互动不通知自己。评论类通知带上笔记 ID、顶层评论 ID 和目标评论 ID，通过上下文接口取得目标所在评论线程，不能假设目标一定在评论第一页。来源笔记或评论不可见时，通知显示“相关内容已不可见”，清除内容预览并禁止跳转。

## 与健身功能的连接

第二期优先增加训练及餐食分享，以复用本项目真实记录形成内容，而不是只提供泛社交信息流。

| 分享入口 | 笔记中可选的快照内容 | 发布前处理 |
| --- | --- | --- |
| 完成训练后 | 训练名称、选中的动作、组数或时长、个人感受 | 用户选择具体字段，预览分享卡片后发布 |
| 今日饮食 | 选中的餐食名称、图片、份量和营养估算 | 用户选择具体餐食，可取消营养数据的展示 |
| 阶段记录 | 用户明确选择的时间段及变化 | 后续扩展，体重和身体照片需要逐项选择 |

分享产生独立的内容快照和社区媒体副本，不直接引用可读取完整个人记录的地址。原记录更新或删除不会悄悄改写已经发布的笔记；用户可以单独编辑或删除分享。餐食 AI 估算保留其来源说明，普通经验内容不展示未经核验的专业认证标记。

“来自训练记录”或“来自餐食记录”说明内容来源，“平台精选”需要真实的管理员操作；不把它们混同为专业审核或效果保证。社区收藏也不会自动修改用户训练计划或饮食账本。

| 次级文字 | `#707184` | 作者、时间和辅助说明 |
| 分隔线 | `#DCDDE9` | 轻量边界 |
| 主按钮 | 背景 `#B8DDF6`，文字 `#245675` | 发布、关注及主要操作 |
| 强调色 | `#5368EE` | 当前标签、焦点和少量强调 |
| 喜欢选中 | `#FF4D67` | 点赞图标选中；数量继续使用主文字色 |
| 收藏选中 | `#B7791F` | 收藏图标选中，配合文字状态 |
| 卡片间距 | 桌面 20px，手机 10 至 12px | 信息流 |
| 圆角 | 封面 14 至 16px，详情 20px，操作按钮胶囊形 | 接近参考图的柔和边界 |
| 动效 | 90 至 300ms | 标签切换、弹层、图标及轻量反馈，遵守减少动态设置 |

点击目标至少 44 × 44px，图标本体可小于该尺寸。点赞、收藏和关注使用图标形态、文字和颜色共同表示状态；键盘焦点清晰可见。详情弹层具备标题、焦点约束和关闭后的焦点恢复，卡片阅读顺序应与键盘导航一致。

详情参照用户提供的 P1、P3：中文无衬线字体，桌面标题 20px/700、正文 16px/400、评论 14px/400；昵称和时间采用灰色正常字重。主头像 40px、子回复头像 28px，保持顶部对齐。详情关注按钮使用红色描边，点赞选中为红色，回复展开按钮及话题为蓝色；其余页面沿用整体配色。

瀑布流实现应保留数据顺序，避免 CSS 分栏造成先读完一列再读下一列的顺序。可用顺序网格配合行跨度形成不同高度卡片，媒体预留比例占位，避免图片加载后大幅跳动。暂时无法稳定排布时，优先保证顺序和位置，再调整视觉高度。

## 数据和接口设计

本节是拟新增的开发契约。现有个人 `records` 和 `/api/sync` 继续承担个人记录同步，社区的跨用户关系使用独立表及独立接口。社区不复用现有私人附件的访问权限，也不依赖个人同步状态判断发布是否成功。

### 核心数据

| 数据表 | 主要字段及约束 |
| --- | --- |
| `community_profiles` | `user_id` 唯一，社区昵称、头像媒体 ID、简介、更新时间；不包含健康档案 |
| `community_accounts` | 用户与唯一 10 位公开账号的固定映射，不随昵称变化 |
| `community_conversations` | 两个参与者及最后消息位置，同一对参与者唯一，禁止自己与自己建立会话 |
| `community_messages` | 会话、递增序号、发送者、文字、时间、请求唯一键；发送者与唯一键的组合唯一 |
| `community_message_reads` | 参与者与会话的已读序号，按收到的消息推进 |
| `community_notes` | 作者、类型、标题、正文、分类、可见范围、状态、处理原因、发布时间、更新时间、版本；状态包括 published、deleted、hidden |
| `community_media` | 上传者、用途、文件类型、大小、宽高、时长、存储位置、上传状态；用途区分笔记素材、社区头像和互动图片，未使用素材仅本人可读 |
| `community_note_media` | 笔记与媒体关联、展示顺序、用途及封面标记；`media_id` 唯一，首期每个素材只属于一篇笔记；用途区分正文图片、视频和视频封面，不能混用头像素材 |
| `community_attachment_media` | 互动图片与评论、私信、群消息的独立绑定及顺序；图片只属于一条内容，删除和权限撤销随目标处理 |
| `community_topics` 和 `community_note_topics` | 规范化话题及关联，同一笔记同一话题唯一 |
| `community_comments` | 笔记、作者、顶层评论 ID、被回复用户、正文、时间、删除状态；限制为一级回复关系 |
| `community_note_likes` 和 `community_collections` | 用户与笔记的唯一关系 |
| `community_comment_likes` | 用户与评论的唯一关系 |
| `community_follows` | 关注者与被关注者唯一，禁止自己关注自己 |
| `community_notifications` | 接收者、事件类型、操作者、笔记 ID、顶层及目标评论 ID、去重键、已读状态和时间 |
| `community_reports` | 举报者、目标类型及 ID、原因、说明、处理状态、处理结果 |
| `community_roles` | 服务端配置的社区管理角色，普通用户不能自行授予 |
| `community_mutations` | 用户、操作类型、请求唯一键和结果，用于发布及评论等操作的重试去重 |

草稿单独存放于账号隔离的 IndexedDB；本期不承诺跨设备同步。社区媒体文件建议置于数据目录下独立的非静态目录，SQLite 保存元信息，读取统一经过鉴权和内容状态检查。

### 第一期接口

所有路径以 `/api/community` 为前缀，沿用当前会话 Cookie 及 `X-Fitness-User` 账号一致性检查，防止其他标签页切换账号后继续提交旧账号数据。写操作继续验证请求来源；服务端从会话取得用户 ID，不接受客户端指定操作者。社区作者响应单独构建，仅返回社区用户 ID、公开账号、昵称、头像和简介，不复用当前包含邮箱的 `publicUser()` 响应。

| 方法及路径 | 用途 |
| --- | --- |
| `GET /feed` | 推荐或关注流，参数含频道、分类、游标及数量 |
| `GET /search` | `type=notes\|users`，查笔记或昵称、公开账号；笔记支持相关程度或最新排序 |
| `GET /me/followers` | 本人粉丝公共资料分页，游标绑定账号，续页排除已取消关注或注销的账号；用于群成员快捷邀请 |
| `GET /messages/unread`、`GET /messages/conversations` | 本人私信未读数量及会话分页 |
| `POST /messages/conversations`、`GET /messages/conversations/{id}` | 建立或复用双人会话，以及参与者读取会话资料 |
| `GET /messages/conversations/{id}/messages`、`POST /messages/conversations/{id}/messages` | 顺序分页读私信和带请求唯一键发送文字、图片 |
| `PUT /messages/conversations/{id}/read` | 按已展示的收到消息推进已读位置 |
| `GET /notes/{id}` | 笔记、作者公开资料、互动计数和当前用户的互动状态 |
| `POST /notes` | 创建笔记，带 `clientMutationId` 和本人已上传媒体 ID |
| `PATCH /notes/{id}`、`DELETE /notes/{id}` | 校验作者及版本后编辑或删除 |
| `PUT /notes/{id}/like`、`PUT /notes/{id}/collection` | 请求体传入明确的 `active` 状态，重复提交得到相同结果 |
| `GET /notes/{id}/comments`、`POST /notes/{id}/comments` | 分页读评论，创建评论或回复；创建使用去重键 |
| `GET /comments/{id}/replies` | 单独分页加载顶层评论的回复 |
| `GET /comments/{id}/context` | 校验可见性后返回顶层评论及目标回复上下文，用于通知定位 |
| `PUT /comments/{id}/like`、`DELETE /comments/{id}` | 评论点赞传入明确的 `active` 状态，重复提交返回相同结果；删除按评论权限校验 |
| `GET /users/{id}`、`GET /users/{id}/notes` | 社区资料及该作者可见笔记 |
| `GET /me/notes`、`GET /me/notes/{id}` | 本人管理视图，可读取自己的下架状态、原因和内容；不改变普通详情的可见规则 |
| `PATCH /me/profile`、`GET /me/collections` | 编辑本人社区资料、分页读取本人收藏 |
| `PUT /users/{id}/follow` | 请求体传入明确的 `active` 状态 |
| `GET /media/{id}`、`HEAD /media/{id}`、`POST /media`、`DELETE /media/{id}` | 授权读取、独立二进制上传、清理未引用素材；视频支持 Range 请求及正确的 206 响应 |
| `GET /media/{id}/metadata` | 查询本人素材的处理状态及到期时间，用于重新打开草稿和发布前校验 |
| `GET /me/media/{id}`、`GET /moderation/media/{id}` | 分别验证本人管理权限及社区管理角色后读取下架素材；已删除内容仍不可读 |
| `GET /notifications`、`PUT /notifications/read` | 获取通知及标记指定项或全部已读 |
| `POST /reports` | 提交内容或评论举报 |
| `GET /moderation/reports`、`PATCH /moderation/reports/{id}` | 社区管理角色读取和处理举报，普通账号拒绝访问 |

信息流返回 `items`、`nextCursor` 和 `hasMore`。游标绑定当前用户、频道、筛选和排序快照，翻页不重新排列已加载数据；快照过期时保留现有页面并提示刷新。作者主页及关注流可用发布时间和 ID 作为稳定排序键。每次翻页、读取通知和详情时重新验证内容可见性，固定快照只保存排序，不让已经下架的内容继续可读。

成功的写操作返回服务端确认的状态及计数。点赞、收藏、关注、计数和通知在同一事务中处理；重试不叠加关系和通知。发布及评论使用请求唯一键，客户端网络中断后可查询或重试原请求，确认结果后再清空草稿。

现有私有附件继续以 Base64 JSON 上传并存储。社区使用独立二进制媒体接口和流式接收，不扩大所有 JSON 接口的上限。服务端检查文件真实格式、图片尺寸、MP4 结构、编码与时长；首期接受完整的非分片 MP4，包含一个 H.264 Baseline/Main/High、8 位 4:2:0 视频轨和可选的一个 AAC-LC 音频轨，最长 60 秒、最大 50 MiB。图片支持 JPEG、PNG、WebP，每张最大 10 MiB；视频封面由用户另行选择图片。首期不自动转码或生成服务器缩略图，不兼容时说明原因并保留草稿。内容安全策略允许同源视频及本机 `blob:` 预览。

对发布、评论、关注、举报和媒体上传分别设置频率或容量限制；失败时给出可重试时间。对内容使用文本转义，避免把用户正文作为 HTML 执行。发布、编辑及更新头像同时验证媒体所属账号、用途、格式、验证状态和有效期；笔记编辑只能保留本篇素材或使用新上传素材，其他笔记的素材需复制后重新关联。

笔记媒体的普通社区读取需在内容删除或下架后立即失效；下架原内容只在本人管理视图及管理员处理队列中通过专用权限读取，已删除内容不提供这一例外。当前社区头像按社区资料的有效引用授权，不能依赖笔记状态判断。所有媒体均经过接口授权，不能永久暴露在静态目录下。未发布素材设定到期清理任务，清理前检查其仍未被有效笔记、社区资料、消息或评论引用；草稿素材过期后重新选择，不显示为仍可发布。

## 页面状态和内容管理

| 场景 | 页面反馈和处理 |
| --- | --- |
| 社区没有内容 | 展示“第一篇训练故事，从你开始”及发布入口；不伪造用户和互动数 |
| 尚未关注作者 | 展示“关注感兴趣的人，他们的新笔记会出现在这里”及返回推荐入口 |
| 收藏或草稿为空 | 清楚说明该区域用途，提供浏览或发布入口 |
| 请求失败 | 保留已加载内容，在失败位置重试，不重置整页 |
| 当前离线 | 可以编辑本机草稿；信息流无响应时提示联网查看，不宣称支持离线媒体浏览 |
| 笔记失效 | 展示“笔记已删除或不可见”，提供返回社区入口 |
| 操作版本冲突 | 保留本地修改并提示重新加载服务端内容 |
| 图片失败 | 使用保持尺寸的占位和重试，不影响其他卡片 |
| 视频无法播放 | 保留封面，说明无法播放，可重试；不显示无限加载动画 |
| 上传超限 | 在素材旁展示大小、类型或时长原因，允许删除及重新选择 |

举报表单使用白色单选列表，原因依次为色情低俗、政治敏感、诈骗信息、种族歧视、站外导流、违法违规、低差广告、不友善、引战、诱导关注点赞、涉未成年人、网络暴力、疑似自残自杀、笔记不相关和其他；“不友善、引战”为一项，共 14 项。原因区域可滚动，标题、关闭和底部粉色提交按钮保持可见。初始不选原因，提交禁用；仅选择“其他”显示选填说明，切换到其他原因时隐藏且不提交该说明，同一表单中切回后保留输入。前后端使用共享理由定义，旧“侵权”理由保持兼容。管理员通过最小处理队列查看原内容，选择保留或下架；对已下架且完成修改的内容可选择恢复，操作均需填写原因并记录操作者和时间，处理结果写入通知。管理角色需由服务端配置，普通社区主页没有申请即获得权限的入口。

管理员的举报处理入口位于社区顶部通知铃铛右侧，使用与消息、通知一致的线条旗帜图标；确认本人管理权限后才显示，个人中心不再重复显示文字入口。窄屏下导航与操作图标分行排列，通知和举报图标仍保持相邻。

举报处理列表以白色卡片展示，分别标注举报来源（笔记、主评论或回复）、内容分类、内容形式、所属笔记和内容作者；举报类别、补充说明、举报人及举报时间单独展示。已处理记录同时展示处理结果、处理原因和处理时间。审核弹窗沿用这些信息，并展示完整原文与说明；列表长文本仅作摘要。目标删除后保留举报信息，内容分类和作者显示“无法获取”，评论类来源标为“评论 / 回复”，不推断已缺失的数据。

下架内容不进入任何普通列表，普通详情地址和普通媒体接口统一不可读。作者在“我的”管理页可看到下架状态和原因，管理角色可在处理队列查看原内容；收藏和通知移除不可见内容预览。社区数据导出与账号删除需要纳入现有个人中心：删除账号时撤下该账号的笔记，处理其评论和关系并清理媒体，其他账号不能再读到其内容。

## 开发接入和验收

前端以 `public/community.js` 负责社区页面与交互，`public/community-api.js` 负责请求和结果状态，`public/community-drafts.js` 负责本机草稿，`public/community.css` 负责社区样式。`public/app.js` 接入导航、路由和会话，社区功能保留独立模块。

输入控件沿用各页面原有的字号、颜色、对齐、高度和提示，保留原生标签、输入法、焦点和选择行为。按用户要求，统一输入样式和短搜索提示方案已回退；用户搜索列表及消息通知导航设计继续保留。

社区需要独立页面状态和详情弹层。点赞及评论只更新相关区域，避免当前整页重新渲染方式重置滚动、输入框和正在播放的视频。记录各频道的筛选、游标、已加载笔记和滚动位置，账号切换时清理内存状态。

后端以 `server/community.mjs` 处理社区规则及接口，`server/community-storage.mjs` 处理独立表和事务，`server/community-messages.mjs` 处理双人私信，`server/community-media.mjs` 处理媒体上传、验证、授权读取及清理，接入现有 `server.mjs` 和存储初始化。静态脚本和样式已更新资源版本及 Service Worker；鉴权 API、草稿媒体和社区媒体本期不纳入离线缓存。

实施顺序建议为页面结构和路由、数据及媒体、笔记发布和详情、互动及作者主页、通知及内容管理，最后完成跨端和异常验收。第二期的健身分享卡片以第一期稳定的数据及发布流程为基础。

| 可访问性 | 键盘可完成浏览和互动，弹层焦点正确，输入不被手机键盘遮挡，减少动态设置生效 |
