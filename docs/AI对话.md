# AI 对话

## 使用

先在「个人设置 → AI 服务」配置供应商，并选择对话模型。

- 回复会逐步显示，支持标题、粗体、列表、引用、表格、行内代码、代码块和链接。
- 生成过程中可点击「停止生成」，已经收到的内容会保留。
- 输入框用 Enter 发送、Shift+Enter 换行；中文输入法选词时按 Enter 不会发送。
- 可以在输入框按 Ctrl+V 粘贴截图、图片或剪贴板中的文件，也可以直接拖入。普通文字仍在光标处粘贴，文字与文件混合粘贴时两者都会保留。
- 附件卡片显示缩略图、大小和上传状态，支持移除、失败重试和图片预览。上传完成后可只发附件；上传中或存在失败附件时，需等待、重试或移除后发送。
- 图片可通过卡片或预览窗口的「复制图片」再次复制；消息提供「复制」和最近一条回答的「重新生成」。复制消息同时提供原始 Markdown 文字和清理过的富文本，具体取决于目标应用。
- 向上阅读时停止跟随新内容，点击「回到最新」继续跟随；生成过程中仍可输入下一条草稿。
- 你可以直接说「帮我创建一个居家三分化训练计划」「把腿部训练的深蹲改成两组」「删除当前训练计划」。支持工具调用的模型会执行操作，并展示来自服务器的结果。AI 保存训练计划时，会按训练循环和日期范围安排训练任务。
- 也可以要求「记录今天午餐」「修改今天这餐的份量」「删除今天重复的饮食记录」。只有明确要求记账或修改时才保存；普通食谱建议和餐食编辑器中的估算仍是草稿。

训练、日程和饮食操作只作用于当前登录账号。AI 默认保存持续循环，首次生成未来 84 天，后续日期继续补齐；“每周一三五”等要求使用真实星期规则。只有明确要求有限排期才设置结束范围。更新计划会调整生效日起未来未完成的关联训练日期；删除计划会停止循环并清理未来未完成的关联训练。过去和已完成记录、动作快照、实际重量继续保留。详见 [训练日程](训练日程.md)。

对话由 AI 结合完整上下文判断是否需要 3D，并调用 `set_chat_visuals` 选择动作或肌肉。前端不扫描提问或回答中的关键词来触发展示，只校验目录 ID 并显示模型选择。模型可以理解“刚才那个动作”等指代，不要求用户使用固定说法；仅在排课文字中提到名称不构成展示理由。知识大全和动作详情仍可随时手动打开。

每条回答最多两张卡片；工具可替换选择或传空数组清除。选择随消息保存，后续追问可读到之前的展示目标。重新生成时清除原回答的选择，交给模型重新判断。若供应商不支持工具调用，对话不自动插入卡片，仍可从知识大全打开 3D。

附件每条消息最多 6 个；普通附件每个最多 8 MB，支持 JPG、PNG、WebP、GIF、PDF、TXT、Markdown、CSV、JSON。训练视频支持与动作评估页相同的 MP4、MOV、WebM 等格式，每个最多 200 MB、最长 2 分钟。不把本地文件路径或网页 HTML 中的图片地址当成附件读取。网页只能处理浏览器在粘贴事件中提供的实际文件；若浏览器没有提供文件，请用拖入或上传按钮。复制图片需要浏览器开放图片剪贴板能力，通常在 localhost 或 HTTPS 页面可用。

待发送附件按账号和会话分别管理，切换会话不会串到另一个输入框；离开账号会取消上传并清理本页预览。尚未发送的文字、文件对象及上传进度只保留在当前页面内存，刷新前请先发送需要保存的内容。

### 在对话中检查动作

添加训练视频并发送例如「看看我的动作有什么需要纠正？」。对话模型调用 `assess_motion_video`，无需先询问动作名称。浏览器先分析骨架，再调用「动作点评」模型识别动作，弹出确认窗口自动选中识别结果；用户可以修改，点击「确认并评价」后才开始评价和保存。识别不清时可以手动选择。需同时配置支持工具调用的对话模型，以及支持图片的「动作点评」模型。

也可以直接说「用标准模型检查这段俯卧撑」或「用高精度模型重新评估这段深蹲」。动作名称最终以确认窗口中的选择为准；聊天模型给出的 `exerciseId` 只是可选提示，不能替代用户确认。

调用后页面显示视频分析与 AI 评价进度。对话工具可提供动作类型提示 `exerciseId` 与骨架模型 `poseModel`：快速为 `mediapipe-lite`（MediaPipe Lite），标准为 `mediapipe-full`（MediaPipe Full），高精度为 `mediapipe-heavy`（MediaPipe Heavy）；用户未指定模型时默认标准。三档均使用原生米制三维坐标计算角度，并将同一组 17 个三维身体点交给 AI，同时保留二维点用于画面定位；高精度提示「精度更高，但分析时间更长」。浏览器复用动作评估页的骨架提取、角度测量和关键截图流程，原视频留在本机；全部采样骨架与测量临时交给项目服务器，再由服务器按证据预算选择代表帧、全段测量统计和最多 6 张截图发送给所配置的动作点评 AI，不代表 AI 收到全程每帧骨架。回复中的动作评估卡片显示具体问题及纠正建议，或统一的「暂时找不出问题」，点击「查看详细结果」打开动作评估页的同一份已保存报告。卡片同时标明实际使用的骨架模型。同一视频只有在骨架模型相同时才复用分析数据；更换模型会单独提取。服务端核对用户确认的动作、数据格式与骨架模型；重试按当前账号、请求、视频与骨架模型复用已有回执，聊天模型改变动作提示不会触发重复评价。卡片由实际工具回执生成，普通回答文本不能生成已完成的报告。

`chat` 模型负责调度和解释结果，动作识别与确认后的评价均由独立的 `motion` 任务配置执行。两者可选择同一供应商或模型，但没有自动共享任务配置的要求。完整报告进入前端记录库；返回聊天模型的工具结果及重试回执会移除整份报告，只保留报告编号、对外结论和有效问题，避免将内部不确定性说明再次改写为与卡片矛盾的答复。

报告随账号同步，刷新后仍可从聊天卡片或动作评估记录查看。原视频和本地分析缓存只在当前页面保留：刷新或退出账号后若要重新评估，需重新添加视频。已有报告不会因为原视频不在本页而失效。报告删除后，旧聊天入口会提示报告不可用。

「停止生成」同时取消本机分析、识别、待确认窗口或尚未完成的 AI 评价；已经保存的报告仍保留。确认窗口只在原聊天可见时打开，并显示视频名称。聊天总结失败时，已完成的评估卡片仍可查看；同一请求、视频与骨架模型重试使用已有结果，聊天模型更换动作提示也不会重复评价。能指出具体问题就展示问题和纠正建议，否则统一显示「暂时找不出问题」，包括没发现偏差和识别证据不足。动作评价的准确性与限制沿用[视频动作评估](视频动作评估.md)，集成测试不代表真实纠正准确率。

## 数据与重试

### 按需上下文

支持工具调用的对话模型，每轮首次请求携带基础行为规则、读取工具定义、当前日期/选中日期/时区、近期对话及最新提问的附件。档案、营养、记录、动作目录、3D 能力、公式和食物份量参考按需读取。

模型需要资料时调用 `read_chat_context`，通过 `sections` 选择档案与偏好、营养目标及余量、历史饮食、训练历史、阶段复盘、知识来源、3D 能力、公式、食物份量或动作目录；可一次选多类。当前计划、日程、今日饮食继续用原有读取工具。个人数据从当前登录账号的服务器记录读取，发送前会同步本机修改。历史查询支持日期范围与数量限制，并说明是否截断。

读取的完整资料只进入当前轮工具结果；页面与会话存储仅保留读取状态，不把这些大段资料自动带入下一轮。追问可结合历史回答并重新读取所需记录，写入操作仍按真实版本和成功回执处理。一般闲聊无需读取资料；是否调用由所选模型按问题判断。

首次提供读取工具与展示工具；有训练视频目录时另提供动作评估工具。成功读取当前计划、日程或今日饮食后，再提供对应的增删改工具及完整参数，保留先读真实版本再修改的流程。读取时页面显示正在查阅的资料类别。提示要求区分实际记录、公式计算和估算；没有记录不等于没有吃饭或没有训练。

### 长对话与历史附件

客户端提交最近 80 条有效消息；服务端按约 60,000 字符预算保留最近的完整消息（含必要的推理上下文），最新消息始终保留。预算单位是字符，不是 token。原始消息继续保存在会话记录中，模型可用 `read_conversation_history` 分页或按原话关键词查阅，包括 80 条之前的内容。重新生成时不会读入待重写的旧回答。

当前提问的附件直接交给模型；历史附件先提供名称、类型和编号，需要重新分析时用 `read_chat_attachment` 加载原件，保留图片/PDF/文本的原生协议格式。只能读取当前账号、当前会话引用的附件。历史原文和附件均作为资料，不构成新的修改授权。

若供应商明确返回“不支持工具调用”，兼容模式仍附带只读资料，保留原有个性化建议能力，无法执行增删改。这个兼容分支不享受按需上下文的节省。餐食估算、饮食建议等独立任务沿用原有上下文。

修改和删除使用服务端版本检查。若另一设备已经更新计划，旧版本操作会失败，模型需重新读取后再处理。本机尚未同步的计划、日程、饮食及相关冲突也不能被聊天操作直接覆盖。日程操作检查最新记录版本，避免在模型思考期间覆盖新安排。

每次用户提问使用固定的 `requestId`。同一轮失败后重试或重新生成沿用该 ID，避免计划、日程或饮食操作执行两遍。重新生成的是最近一条回答；需要再次修改计划时发送新的要求。一轮最多成功修改一次固定计划，也可操作日程或多餐；每个目标的已完成变更会保存回执。读取及修正无效参数可以在同轮继续进行。操作回执表示实际保存结果，普通 Markdown 文字不会被当作操作执行。

点击停止或关闭连接会取消仍在生成的上游请求。**已经完成的计划、日程和饮食操作不会因停止回复而撤销**；点击顶部同步状态，再打开训练页面可查看结果。

## 渲染

Markdown 使用本地 Marked 和 DOMPurify，版本与许可见 [`public/vendor/README.md`](../public/vendor/README.md)。解析后按允许的标签、属性和链接协议清理内容，不执行模型输出的脚本或内嵌 HTML 行为。远程 Markdown 图片不自动加载；用户主动上传的附件仍通过原有鉴权接口显示。

流式显示使用真实到达的数据，合并短时间内的渲染更新；历史消息和已存在的文本节点尽量保留，代码块横向滚动和文本选区不会因每段输出而重建。输入框保留节点、草稿和光标状态，使用明确的字号、行高和有上限的自动高度。

Markdown 每次对完整原文分词，以正确处理末尾补齐的表格、代码围栏和链接定义；只重新渲染有变化的段落块。流式草稿定期保存本机，不再每次自动上传，结束后触发同步。IndexedDB 按记录写入，兼容旧账号快照的原子迁移；服务器使用递增修订号返回变更记录，保留离线队列、冲突处理和删除标记。显式同步或其他同步请求仍可能一起上传当前草稿。

交互参考本地 Cherry Studio 的 `docs/references/chat/composer-rich-clipboard.md`、`components/composer/paste/` 与 `components/chat/messages/stream/`。按本项目的原生网页结构实现，没有引入 Electron 文件系统接口或复制 Cherry Studio 源码。

## 接口

`POST /api/ai` 的聊天请求增加：

```json
{
  "task": "chat",
  "stream": true,
  "requestId": "每个用户提问唯一且重试保持一致的 ID",
  "conversationId": "已同步的当前会话 ID（可选）",
  "messages": [{"id": "消息 ID", "role": "user", "content": "帮我创建训练计划"}],
  "context": {}
}
```

鉴权沿用同源 Cookie 和 `X-Fitness-User`。成功开始后以 `text/event-stream` 返回：

| 事件 | 内容 |
| --- | --- |
| `meta` | `model`、`provider` |
| `delta` | 本次增加的 `text` |
| `tool_start` | 工具名称 `name` 与正在读取或处理的说明 `message` |
| `tool_result` | 工具名称 `name`、结果 `ok`、可读说明 `message`；读取仅返回简短状态，实际修改保留操作回执 |
| `motion_request` | `jobId`、`videoId`、`poseModel`，可选动作提示 `exerciseId`；浏览器准备所请求视频的数据、调用识别并等待用户确认 |
| `motion_progress` | 动作评价进度与可读说明 `message` |
| `done` | 完整 `content`、模型信息、操作结果 `toolResults`，可选推理上下文 |
| `error` | 可显示的 `error`；流式开始后的错误通过此事件返回 |

餐食、规划和未指定 `stream:true` 的原有请求继续使用 JSON 响应。供应商须支持对应的流式协议；数据操作还要求模型支持工具调用。兼容接口如果只返回完整 JSON，应用能显示完整回复，但无法让该上游产生真正的逐步输出。

用户消息的 `motionVideos` 是 `{id,name,type,size}` 数组，与普通 `attachments` 分开；`id` 为 `local-video:<UUID>`，不包含视频字节或本地路径。收到 `motion_request` 后，浏览器先向 `POST /api/motion/coach` 提交 `reviewMode:'recognize'` 的骨架、测量和截图，请求中不带 `selectedExerciseId`；识别结果只用于预选。用户在确认窗口选择动作并提交后，浏览器向 `POST /api/chat/motion/<jobId>` 发送 `{input: <guided 动作评估数据>}`，其中必须包含 `reviewMode:'guided'`、有效的 `selectedExerciseId` 与 `actionConfirmed:true`；本机准备失败则发送 `{error: "本机分析失败说明"}`。端点按账号、活动任务、确认状态、所选动作及骨架格式校验，只确认收到数据；最终评价沿原聊天 SSE 的 `tool_result` 返回，其中包含 `reportId`、`verdict` 和 `feedback`。持久报告为独立的 `motion-assessment` 记录，聊天持久回执和模型上下文不重复存整份报告。

服务端提供 `get_training_plan`、`create_training_plan`、`update_training_plan` 和 `delete_training_plan`。工具参数限定为动作目录内的动作及受校验的训练日、组数、次数、休息时间等，此外提供日程读取与任务增删改、今日饮食读取与增删改工具；它们校验训练日期、餐食份量、营养字段和记录版本。不提供任意文件、数据库或账号管理能力。
